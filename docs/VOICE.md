# 绒球 · 语音三层与第三层设计（草案 v0.1）

| 项 | 内容 |
|---|---|
| **文档性质** | 设计草案。**未实现、未立项、未改任何红线** |
| **日期** | 2026-10-20 |
| **对应代码** | 无。入口只有 `nucleus.transcribe()` 的 stub |
| **一句话** | 第三层不是「让绒球会读情绪」，是「让系统多一条不靠用户自述的探测通道」 |

---

## 1. 三层定义

| 层 | 做什么 | 现状 | 护城河 |
|---|---|---|---|
| **第一层** | 语音 → 文字（WER） | 大厂 ASR、所有语音输入法 | 红海，接近商品 |
| **第二层** | 文字 → 语义（听懂说了什么） | LLM 助手 | 正在商品化 |
| **第三层** | **声音 → 状态 → 结构**（怎么说、处于什么状态、这个状态指向哪个面） | 几乎无人做 | 空地 |

**为什么第三层是空地：**

- 它缺的不是模型，是**标签**——而标签只在「有产品闭环、用户愿意确认、结果能被回收」的地方长出来；
- 公开情绪数据几乎都是表演的，学术 benchmark 和真实场景差一个量级；
- 大厂做通用 API，不会为垂直场景做最后 10% 的个人化——不划算。

**和绒球自己的「三层完善」是同一个形状：**

```
第一层  用户自述的表层处境        ← 用户给的
第二层  全网同构场景（用户认领）   ← 检索 + 用户确认
第三层  系统主动探测还没说的面     ← 系统自主
```

语音第三层 = 给「系统主动探测」多一条通道。**不是加功能，是补同一个设计缺的那块。**

---

## 2. 第三层的唯一输出（三样，都在现有红线内）

| 输出 | 是什么 | 边界 |
|---|---|---|
| **① 探针决策** | 这个状态先问哪一类面（时间压力？身体？关系？） | 只影响「问什么」，不影响「怎么判」；选择理由公开可查 |
| **② 半知候选** | 系统注意到、但用户还没确认的面 | 用户确认后才升级；不确认就丢 |
| **③ 安全触发** | 声学异常的低阈值触发 | 只出固定求助面板，不出结构、不记录；宁误报 |

**明确不做：**

- ❌ 情绪报告（「你现在很焦虑」）——那是替用户定义感受；
- ❌ 声纹识别 / 说话人身份——生物特征，和「越少越好」冲突；
- ❌ 进事实层 / 进 N——状态不是用户陈述，也不是真实交换（不变量三）；
- ❌ 常驻监听、主动唤醒、云端 ASR——见第 6 节。

---

## 3. 标签 schema（最关键，定错则数据全废）

**原则：标签只来自用户确认，且必须与判断结果解耦。**

- **采集时机**：一次判断**结束之后**（不是看到「更可能是：不会」之后立刻问——那是污染）；
- **采集方式**：用户主动点「这次说的时候，你的状态是？」→ 三个相对滑块（比平时快/慢、紧/松、急/缓，各 −2…+2）+ 可选一个词（紧张/疲惫/兴奋/平静/说不上来）；
- **可拒绝**：跳过即不采，不追问；
- **存什么**：
  - 本机存：**声学特征摘要**（韵律、语速、能量、停顿，去掉说话人身份信息）+ 用户确认标签；
  - **不存原始音频**，不上传，可一键删除；
- **和什么配对**：同一次判断的「挑出了哪些问句 / 用户答了哪些 / 放弃哪些 / 事后回收结果」——这是别人没有的标签闭环；
- **门槛**：样本 < N（建议先定 200）时**不启用**，沉默是设计。

```
feature(本机) + 用户确认标签 + 探针结果 + 回收结果
        → 个人基线模型（few-shot 校准）
```

**自研 ≠ 从零训大模型。** 正确的形态是：开源语音骨干（WavLM / HuBERT / emotion2vec / SenseVoice 一类）+ 说话人归一化 + 你的标签做个人化微调。核心 IP 是**标签 schema 和闭环**，不是网络结构。

## 4. 任务级指标（不许用 SER benchmark 分数当成功标准）

| 指标 | 定义 | 用途 |
|---|---|---|
| **探针收益（主指标）** | 加状态先验后，选中的问句「被回答/被认领」的比例、结构补全率（N 增加量）是否上升 | 决定第三层是否保留 |
| **回收校准** | 有/无状态先验两组，回收后的 Brier / 命中率差 | 长期主指标 |
| **标签复现性** | 同一状态跨天复现率、跨设备一致性 | 模型质量 |
| **误报率 / 拒绝率** | 半知候选被用户否定的比例 | 信任成本 |
| **弃权率** | 模型判不准时选择不用的比例 | 沉默质量 |

**先决条件：A/B 或交错实验，本机统计；不对外宣传「情绪识别准确率」。**

## 5. 红线对照

| 红线 / 不变量 | 第三层 | 约束 |
|---|---|---|
| 一 · 不替用户决定 | ✅ 不触碰 | 只出探针与元信息；选择理由公开 |
| 二 · 他人观点零权重 | ✅ 不触碰 | 状态不是事实；不进事实层 |
| 三 · 不卖注意力 | ✅ 不触碰 | 不做时长/唤醒优化；「依赖度下降」仍是唯一成功标准 |
| 四 · 内容不出设备 | ✅ 需守住 | 音频不落盘；特征只在本机；无云端；可删 |
| 五 · 不隐藏 | ✅ 需守住 | 算法公开；误报公开；负结果公开 |
| 不变量三 · N 可追溯 | ✅ 需守住 | 只有用户点击才能进 N；状态只能当候选 |
| 安全例外 | ✅ 加强 | 只触发固定面板；不记录；宁误报 |

## 6. 不在这份设计里的（要另走程序）

- **常驻监听 / 主动唤醒 / 没打开 App 也服务**：会改变产品形态（从「你来找它」变成「它一直在你身边」），与「依赖度下降」冲突；若要，走 REDLINES 第六部分变更程序（30 天冷静期 + 外部复核）；
- **云端 ASR / 云端情绪模型**：红线四直接否决；
- **按情绪做内容/推荐**：PROPOSAL 9.3 明确把「按用户情绪」列为画像，不做。

> 常驻还有一个数据质量理由：用户一旦觉得总在被听，就会开始管理自己的表达——**真实信号消失，标签变假，模型必然不准**。隐私不是道德约束，是准确率前提。

## 7. 阶段计划（研究线，不阻塞 P0 / P2）

| 阶段 | 做什么 | 门槛 / 产出 |
|---|---|---|
| **V0（现在）** | ASR + 回显确认（第一层通道） | 桌面 localhost 可用；音频不落盘 |
| **V1** | 标签采集钩子（事后、解耦、可拒绝） | 采到第一批确认样本；隐私测试通过 |
| **V2** | 个人基线模型（离线） | 任务级探针收益显著 > 基线；误报可接受 |
| **V3** | 接入选问句先验（默认关闭，可开） | 复盘：收益真实、无引导风险、红线审计通过 |

**Go / No-Go：** V2 如果做不出任务级收益，就停在 ASR，公开负结果（红线五）。**不为了「做了三年」而硬推。**

---

## 8. 一句话总结

> **第三层不是「让绒球会读情绪」，是「让系统多一条不靠用户自述的探测通道」。**
> **它的准确性由标签闭环决定，不由模型决定。**
> **它的边界是：只影响问什么，永不影响怎么判，且用户先确认。**
