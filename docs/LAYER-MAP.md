# 层地图 v0.1

日期：2026-10-22  
用途：把绒球的「流水线层」和「底座层」分开看。以后讨论「下一步做什么」，先对这张图，不要只对功能列表。

状态图例：已有 / 雏形 / 只有文档 / 未开始。

---

## 0. 总览

    纵向流水线：
    输入 → 分析 → 计数 → 输出
         ↘ LLM（可插拔，不是主干）
    校准、测评：横切所有层
    UI / 上线：最后，但底座必须提前

    底座层（B 系列）：
    B1 数据与记忆      B2 身份与多主体    B3 隐私与安全
    B4 知识工程        B5 可解释与审计    B6 时间与生命周期
    B7 部署与更新      B8 质量保证        B9 商业与治理
    B10 多模态/移动端/可访问性/国际化       B11 可观测/性能/错误

底座层不是「以后再说」，它们决定上面能盖多高；但也不是都要第一天做完。

## 2. 真正漏掉的底座层（重点）

### B1 数据与记忆层 — 雏形

- 职责：决策记录、修订、回收、导出、删除、备份、压缩、跨设备同步。
- 现状：journal 是 JSONL；有 decision_id / revision / resolve；无 schema version、无迁移、无导出/删除 UI、无备份。
- 为什么是底座：用户信任的第一条是「我的东西能不能拿走/删掉」；没有它，校准做得再好也不敢让真实用户进来。
- 缺什么：数据 schema v1、迁移、export/import、delete、备份、加密、压缩、同步。
- 完成判据：能导出全部数据、能真删、能跨版本升级、损失可恢复。

### B2 身份与多主体层 — 未开始

- 职责：用户、设备、房间、成员、权限、同意。
- 现状：单机单用户；决策房间只在立项书里。
- 为什么是底座：递归 N11 / 家庭房间没有身份和权限就是偷看。
- 缺什么：身份、房间、邀请、权限、同意、退出、数据隔离。
- 完成判据：两个用户能开一个房间，彼此只看到被允许的共享事实。

### B3 隐私与安全层 — 只有文档

- 职责：本地加密、密钥、最小化、危机安全、未成年人、医疗/法律边界。
- 现状：PRIVACY / DATA-CONSTITUTION / REDLINES 有原则；代码里只有 crisis 关键词短路。
- 为什么是底座：一次泄露或一次越界建议，产品就结束。
- 缺什么：威胁模型、加密、密钥管理、删除、危机转介、免责与合规。
- 完成判据：威胁模型经过外部审阅；数据默认不出设备；删除可验证。

### B4 知识工程层 — 雏形

- 职责：面库、probe、lexicon 的编辑、来源、版本、审核、去重、覆盖度、翻译。
- 现状：JSONL + 脚本 + 审计脚本；没有编辑流程、没有版本、没有来源字段的强制校验。
- 为什么是底座：面库是护城河，但护城河需要维护队；没有编辑流程，库会烂。
- 缺什么：编辑规范、审核人、版本、回滚、覆盖度报告、来源与许可。
- 完成判据：每次改库可追溯、可回滚；覆盖度可量化。

### B5 可解释与审计层 — 雏形

- 职责：CIR 契约、ir_hash、可复现编译、为什么问这句、为什么这个面。
- 现状：INPUT-LAYER 文档 + input_layer 代码；产品 API 还是临时 dict；CIR/AIR 在私有原型，未进产品。
- 为什么是底座：用户要能问「你凭什么这么问」；没有它，信任只能靠话术。
- 缺什么：IR v1、hash、trace、用户可见的解释、回归测试。
- 完成判据：同一个输入编译结果可复现；用户能看到面/缺口/问句的来源。

### B6 时间与生命周期层 — 雏形

- 职责：决策状态机（open / pending / resolved / abandoned / expired）、提醒、到期、回访。
- 现状：resolve_by + 回收页；没有提醒、放弃、过期、删除。
- 为什么是底座：低频高权产品靠「该回来的时候回来」，不是靠日活。
- 缺什么：状态机、提醒纪律、放弃/过期、回访文案。
- 完成判据：用户知道什么时候会再被联系；可以主动放弃；不会被打扰。

### B7 部署与更新层 — 雏形

- 职责：构建、签名、安装、自动更新、回滚、崩溃上报。
- 现状：本地 PyInstaller + WebView2 脚本；无 CI、无签名、无 updater。
- 为什么是底座：装不上/更新坏一次，用户就没了。
- 缺什么：CI、签名、安装器、更新通道、崩溃采集（隐私最小化）。
- 完成判据：新版本可灰度、可回滚；崩溃可定位。

### B8 质量保证层 — 雏形

- 职责：单测、集成、端到端、属性测试、模糊测试、性能、可用性。
- 现状：211 个单元测试；无 UI e2e、无 811 不变量属性测试、无性能预算。
- 为什么是底座：测试不是测评；代码对不等于产品对。
- 缺什么：e2e、属性测试、性能基线、可用性测试、红队。
- 完成判据：关键路径有 e2e；811 不变量有属性测试；有性能预算。

### B9 商业与治理层 — 只有文档

- 职责：许可、贡献、维护者、资金、合规主体、发布节奏。
- 现状：有 LICENSE / CONTRIBUTING；没有治理结构、没有资金安排。
- 为什么是底座：代际方法需要活得比作者久。
- 缺什么：治理规则、维护者、资金/合规、发布节奏。
- 完成判据：有人能接；有可持续的维护方式。

### B10 多模态 / 移动端 / 可访问性 / 国际化层 — 只有文档

- 职责：语音、手机端本地记录与导出、屏幕阅读、键盘、i18n、时区、本地化。
- 现状：VOICE 只有设计；UI 无无障碍；lexicon 只有中文；**没有手机端**。
- 为什么是底座：语音是第一接触面的自然入口；手机是家属/警方最可能直接拿到的设备；无障碍是底线。

**手机端本地记录 + 本地导出（优先子项）：**

- 记录：手机本地保存危机第一接触面（问题 / 时间 / 地区），与桌面同一套 schema v2；
- 查看：手机上的「本机记录」列表，只显示问题、时间、地区，不显示历史判断；
- 导出：一键导出到手机 Files/Documents，生成 JSON、摘要.txt、SHA-256 清单；
- 分享：用系统分享/数据线/U 盘交给警方或家属，**不经过云端**；
- 跨设备：电脑与手机用局域网二维码配对，只做本地只读/导出，不建服务器副本；
- 安全：应用锁/生物识别、导出二次确认、锁屏不显示敏感内容、默认不自动云备份；
- 完成判据：手机离线能查看、能导出；警方拿到的是可核验文件夹；没有任何自动上传。

- 缺什么：移动端壳（原生/PWA）、本地存储与加密、导出/分享、局域网配对、a11y、i18n、时区。
- 完成判据（整体）：核心流程可键盘完成；至少一种语音输入；至少一种第二语言；手机端可离线查看并导出危机记录。

### B11 可观测 / 性能 / 错误层 — 雏形

- 职责：结构化日志、隐私遥测、性能预算、错误分类、降级 UX。
- 现状：app.log + 错误提示；无指标、无预算。
- 为什么是底座：20–40 秒的 LLM 调用、离线降级、搜索失败都需要被看见。
- 缺什么：日志规范、指标、预算、错误码、降级策略。
- 完成判据：线上问题能定位；用户看到的是可行动的提示。

## 3. 层间契约（先冻结，再盖楼）

至少要有这几条接口：

- 输入 → 分析：Nucleus / Frame / Surfaces / Gaps / Probes
- 分析 → 计数：Facts（text, supports, source, surface, depth）
- 计数 → 输出：Judgment（lean, confidence, N, determinability, p_yes）
- 输出 → journal：decision_id / revision / resolve_by / surface_answers
- 校准 ← journal：outcome / user_lean / p_yes / surface

没有契约，层与层会偷偷替对方做决定——这是比缺功能更大的风险。

---

## 4. 最小纵切（建议先做穿这条）

    一个用户 · 一台设备 · 一个决策
    输入 → 分析 → 计数 → 输出 → 回收 → 校准

同时带上四根底座的最小版本：

- B1：导出 / 删除 / 备份 / schema version
- B3：本地数据最小化 + 危机处理
- B5：IR v1 + 可复现编译
- B7：CI + 签名 + 可回滚的构建
- B8：关键路径 e2e + 独立测评

这条打穿之后，再谈房间、语音、多语言、商业化。

## 5. 优先级

**P0：不完成就不该让真实用户进来**
B1 数据生命周期 / B3 隐私与安全 / B5 可解释与审计 / B7 更新与签名 / B8 测评 / B6 提醒纪律。

**P1：决定产品能不能变好**
B4 知识工程 / B11 可观测 / V2 分析 / V5 校准。

**P2：规模与形态**
B2 身份与房间 / B10 移动端与 i18n / B9 商业与治理 / V8 移动端。

---

## 6. 三个容易误判的地方

1. **有模块 ≠ 有层**：topology / common_root / drift 有代码，但没有稳定接口和用户价值闭环，还不是「层」。
2. **有文档 ≠ 有执行层**：PRIVACY / REDLINES 写得再好，加密、删除、危机转介没有落地，就等于没有。
3. **有测试 ≠ 有测评**：244 个单测证明代码没坏，不证明产品有用。

---

## 7. 变更规则

- 新增一层，必须在本文档写：职责、输入/输出、现状、完成判据。
- 任何一层不得替另一层做决定；跨层只能走契约。
- 每季度重看一次本图；层可以合并，但不能悄悄消失。
