# 一、项目概要

**绒球是一个个人决策校准系统。**

用户带着一个正在犹豫的问题进来，系统把它拆成结构：

- **N 个事实面**（支持 / 反对，严格二元）
- **1 个半知**（隐约知道但未验证的东西）
- **1 个未知**（明确不知道自己不知道的）

然后给出一个**参考倾向 + 置信度**，并记录归档；到期回收结果，形成用户本人的校准曲线。

**它不预测未来，不给建议，不替用户做决定。**

# 二、问题陈述

## 2.1 我们原来在做什么

项目前身是一个量化交易系统（quant-lab），做过七套策略，最终全部被否决：

| 结论 | 数据 |
|---|---|
| 成本吞掉一切 | 双边成本 14bps，最好的边际 0.95bps |
| 分散化是乘数不是加数 | 无法替代正期望 |
| 样本外表现 | Sharpe 0.05 vs BTC 0.76 |

**结论：在完全竞争的市场里，个人无法靠信息优势取胜。**

## 2.2 真正的缺口

**市场上所有的信息产品，都在解决「你不知道什么」。**
**没有一个在解决「你不知道自己不知道什么」。**

具体表现：

1. **信息过剩，判断力稀缺。** 一个人可以做十次搜索，却仍然不知道自己在犹豫什么。
2. **AI 替代判断。** 主流 AI 给答案，用户逐渐失去自己做判断的能力。
3. **他人的观点被当成证据。** 舆论、统计、专家意见被大量当作事实使用。
4. **没有校准。** 没有任何工具记录「你说过的判断，后来对不对」。
5. **过度自信是系统性的。** 人工智能越是自信地给答案，这个问题越严重。

## 2.3 目标用户

| 阶段 | 用户 | 场景 |
|---|---|---|
| 第一阶段 | 个人用户 | 日常犹豫：去不去、要不要、说不说 |
| 第二阶段 | 管理者 / 创业者 | 高价值决策：招人、投入、放弃 |
| 第三阶段 | 组织 | 决策复盘、组织校准 |
| 第四阶段 | 教育 | 青少年决策习惯养成 |

# 三、核心主张

> **判断一个事物的方向，要找到与它直接接触的实体，然后判断那个实体。**

这句话是全部设计的地基。它推出四个可执行的原则：

## 3.1 第一接触面 = 马尔可夫毯

**只找直接因、直接果、共同原因。**

给定马尔可夫毯，该节点与其余世界条件独立。**所以只看直接接触的面，就足以判断——不多也不少。**

这就解释了为什么「链长 ≤ 3」：越过两跳的信息，是别人对世界的判断，不是世界对这个节点的直接作用。

## 3.2 他人观点零权重

**别人的看法不是外部力量，是回声。**

信息瀑和回音室摧毁独立性，相关意见不携带新信息。**聚合只会放大误差。**

## 3.3 8020 不是估的，是封顶的

```
可确定 = min(N / (N + 2), 0.8) × 0.8^(链长 - 1)
剩余 20% 对半分：10% 半知 + 10% 未知
```

**N 再多也超不过 80%。**

理论依据两条：
- **毛球定理**：一定有盲区（拓扑必然）
- **必要多样性定律**：世界无限、视野有限（信息论必然）

## 3.4 事实二元，中性只属于 11

**事实层只有支持 / 反对。**
**中性只存在于半知和未知两个槽里。**

不作弃权——因为不决定本身就是一种决定。

### 半知的准确定义（2026-10-19 修正）

**之前理解错了，把半知当成「系统替用户假设一个结论」——那是把它降级成猜测。**

**正确：**

> **半知 = 系统已经找到、但用户还没确认的那一半第一接触面。**

```
N     事实面  =  信息在用户侧，已确认
1 半知        =  信息在系统侧，用户未确认
1 未知        =  信息不在任何一侧
```

## 3.5 11 必须是「死」的，直到问句库建好

**这条是一个硬约束，不是待办。**

**原因：半知的内容来自「系统对原核另外那些第一接触面的探测结果」，
而探测靠问句库——一句问句就是一次探测。**

**问句只有 2 句时，只能探测 2 个面，探出来的缺口不构成「另一半」。**

**填一个假半知，比空着更糟——因为那会让用户以为系统知道些什么。**

**解锁条件见 M1。**

# 四、产品定义

## 4.1 它是什么

| | |
|---|---|
| 输入 | 一句自然语言的犹豫 |
| 处理 | 拆主谓宾 → 找第一接触面 → 判定方向 → 计数 |
| 输出 | 一个结构 + 一个倾向 + 一个置信度 |
| 沉淀 | 判断归档 → 到期回收 → 个人校准曲线 |

## 4.2 它不是什么

- ❌ 不是搜索引擎
- ❌ 不是一个给答案的 AI
- ❌ 不是算命、不是人生规划
- ❌ 不是心理咨询
- ❌ 不是决策自动化工具

## 4.3 核心交互原则

| 原则 | 实现 |
|---|---|
| 能用点就不打字 | 固定询问面：是 / 否 两键 |
| 结论优先 | 结论占一屏最显眼位置，明细默认收起 |
| 不引导 | 只给结构，不给方向建议 |
| 可追溯 | 依据全公开，任何结论都能查 |
| 少即是多 | 一屏只显示必要的三样东西 |

# 六、潜藏能力（框架里已有、尚未使用的）

**下面这六种能力，不是新设计。**

**它们是从现有公理往回推出来的——结构里本来就有，只是我们一次都没用过。**

推导的起点只有一句：

> **绒球不只有「一次判断」，它有「判断的结构」。**
>
> **而结构可以比对、可以叠加、可以排序、可以纵向看。**

**主流软件只有「内容」，所以只能做推荐。**
**绒球有「结构」，所以能做的事是另一个维度。**

---

## 6.1 跨决定的共同根因 —— 五件事其实是同一件事

### 框架为什么支持

**每条事实都有「方向」，而方向是相对于某个二元的。**

```
「老张邀请了我」
  →  支持「去聚餐」
  →  反对「今晚早睡」
  →  支持「见老同学」
  →  反对「省钱」
```

> **同一个事实，对不同的决定有不同的方向。**

**所以可以反过来建索引：事实 → 它影响的所有决定。**

### 它回答什么

> **「你这周在纠结的 5 件事，其实有 3 件是同一个根。」**

**人以为自己有五个问题，其实常常只有一个。**

### 实现要点

- 建立「事实 → 决定」的反向索引
- 用事实的主谓宾做归一化匹配
- 输出：一组共享第一接触面的决定，以及那个共同的面

**这是「结构」这个设计最没被用掉的一次幂。**

---

## 6.2 决策的拓扑排序 —— 哪个决定在最上游

### 框架为什么支持

**每个决定都有第一接触面，而有些接触面本身就是另一个决定。**

```
换工作  ←  第一接触面：要不要搬家
搬家    ←  第一接触面：要不要和伴侣异地
异地    ←  第一接触面：伴侣愿不愿意
```

> **决定之间有依赖关系，而依赖关系是可以画的。**

### 它回答什么

> **「你正在做的这些决定，上游是那个。」**
> **「先做上游那个，下游的会自动简化。」**

**大多数人卡住，不是因为选不出，是因为在同时解五个方程。**

### 实现要点

- 检测一个决定的接触面是否命中另一个待决定义
- 建立有向依赖图，检测环
- 输出拓扑序，标出根决定

---

## 6.3 框架效应检测 —— 换个说法，答案还一样吗

### 框架为什么支持

**绒球的输入是自然语言，而自然语言的表述方式会改变判断。**

```
「我有 70% 机会成功」   vs   「我有 30% 机会失败」
——同一个事实，人的选择常常不一样。
```

### 它回答什么

**同一件事，换三种说法各判一次：**

| 结果 | 说明 |
|---|---|
| 三次一致 | **你的判断是稳的** |
| 三次不一致 | **你被表述方式左右了** |

> **「同一件事，你换了说法就换了答案——说明你还没想清楚。」**

**这不是批评，是诊断。**

### 实现要点

- 生成同一决定的 2–3 种等价表述
- 分别走完整判断流程
- 比较结论方向与置信度
- 输出一致性分数

**注意：这是「测用户」，不是「教用户」。不得提示哪种说法才是对的。**

---

## 6.4 判断漂移 —— 一周后再判，什么变了

### 框架为什么支持

**每条判断都带时间戳、置信度、N、链长。**

**所以可以做纵向对比：**

```
3 月 1 日：  支持 2 / 反对 3   可确定 61%
3 月 8 日：  支持 4 / 反对 3   可确定 70%
```

### 它回答什么

> **「这两个星期，是事实变了，还是你变了？」**

**如果是事实变了 → 你该更新判断。**
**如果是你变了、事实没变 → 那是情绪在替你判。**

### 实现要点

- 用主谓宾 + 原核做同一决定的识别
- 比较两次的事实集合差异（新增 / 消失 / 翻转）
- 把差异分成「事实变化」和「判断变化」两类

**——这是「漂移」和「成长」的区别，而以前没人分得清。**

---

## 6.5 沉默的面 —— 你说出 3 个，这类决定通常有 7 个

### 框架为什么支持

**811 里 N 是可数的，而 N 有一个「期望值」。**

**同一个类型的决定，大量用户的第一接触面数量会收敛到一个区间。**

### 它回答什么

> **「你说出来的面有 3 个。这类决定，通常有 6–8 个。」**

**它不说你漏了哪几个（那是引导），只说「你的面数偏少」。**

### 实现要点

- 按决策类型统计 N 的分布（中位数 + 分位区间）
- 只输出「偏少 / 正常 / 偏多」，不输出缺哪几个
- 隐私要求：只能用聚合分位数，不能反推个体

**——这是「N 是发现的」这句话的反面用法：**
**不只发现你的 N，还能发现「你的 N 够不够」。**

---

## 6.6 校准缺口预警 —— 你的数字比你的历史高

### 框架为什么支持

**它有你的历史：你在这类决定上说过多少次 80%，实际命中多少。**

### 它回答什么

> **「这次你说 85%。但你在这一类上，历史命中是 61%。」**

**——这不是建议，是把你的历史摆在你面前。**

### 实现要点

- 按决策类型维护个人校准曲线
- 当前置信度 vs 该类历史命中率 → 缺口
- 缺口超过阈值才提示，且只陈述数字

**这是唯一一种「用数据帮你」又不算引导的方式：**
**因为它说的是「你以前是什么样」，不是「你这次该怎样」。**

---

# 七、这六个能力的共同点

**它们全部来自同一件事：**

> **绒球真正的能力不是「帮用户判断什么」，是「让判断本身变得可观察」。**

```
一次判断           →  答案
一百次判断         →  画像
一百次判断的结构    →  一个人的思维解剖图
```

**那才是它最后会长成的东西。**

# 九、日活层：讯息与声景

## 9.1 为什么需要日活层

**绒球的价值层是低频的——一个人一年认真做决定的次数是几十次，不是几百次。**

**这带来一个产品问题：低频的东西，用户会忘。**

**所以需要一个「高频、低权、无商业目标」的东西带着它。**

```
日活层（每天打开）  →  讯息 + 声景
价值层（每季度用）  →  决策判断
```

**但日活层有两个必须守住的铁律：**

### 铁律一：永远不赚钱

**用来维持频率的那一层，不许有收入。**

**因为它一旦要赚钱，就会开始劝你。**

### 铁律二：永远不引导

**日活层只提供「此刻的世界是什么样」和「此刻有什么声音」。**

**不提供「你此刻该怎样」。**

---

## 9.2 第一类内容：讯息

### 已实现

| 讯息 | 来源 |
|---|---|
| 时间（几点、周几、是否工作日） | 本地 |
| 位置（省 / 市 / 区） | BigDataCloud 反查 |
| 天气（温度、天气、湿度、日出日落） | Open-Meteo |
| 公共状态（交通运行、设施开放） | 预留 |

### 五条准入门径

**任何新讯息接入，必须过这五关：**

| # | 维度 | 引导（❌） | 讯息（✅） |
|---|---|---|---|
| 1 | 有无方向 | 暗示「你该做 X」 | 只陈述状态 |
| 2 | 是否个性化 | 按你的决定定制 | 对所有人一样 |
| 3 | 是否计入结构 | 进 N 或进 11 | 只展示，不进任何一格 |
| 4 | 是否制造紧迫 | 倒计时、机会流失 | 无时间压力 |
| 5 | 谁筛选它 | 系统按影响力挑 | 固定、公开、可关 |

**五条全过 = 讯息。任何一条不过 = 引导。**

**并且只收裸数据，不收加工过的数据：**

```
✅ 收：温度 13°C、湿度 97%、天气代码 61
❌ 不收：「今天适合外出」「建议改乘地铁」
```

**前者是信号，后者是结论。解释权必须留在绒球手里。**

---

## 9.3 第二类内容：声景（新增）

### 定位

> **不是你该听什么，是此刻有什么。**

**和天气一样：不针对你，不建议你，只是「在」。**

### 为什么是声景，不是音乐推荐

| | 推荐（❌） | 声景（✅） |
|---|---|---|
| 依据 | **你是谁** | **此刻是几点** |
| 个性化 | 按你的情绪 | 对所有人一样 |
| 谁决定 | 系统推送 | **用户自己选** |
| 目标 | 让你多待 | **让你有地方待** |
| 数据 | 你的状态 | **曲子的质量** |

**它没有推荐算法。它只有一份按时刻组织的公共曲库。**

### 四条硬约束（不可修改）

#### 约束一：物理隔离——判断流程中绝对静音

**这是最重要的一条。**

**音乐没有告诉你选什么，但它会改变你的情绪——而情绪会改变判断。**

```
你正在判断「要不要去聚餐」
背景放着一首让人放松的曲子
        ↓
你的「疲惫感」被放大
        ↓
系统判出「反对」
```

**这在方法论上等于作弊：音乐污染了第一接触面的判定。**

**所以规则是「空间关系，不是流程关系」：**

> **判断在屋里，音乐在窗外。**
> **窗外的雨声可以存在，但它不能改变屋里的测量。**

| 场景 | 音乐 |
|---|---|
| 判断流程中 | **绝对静音** |
| 等待结果的 20–40 秒 | **绝对静音** |
| 打开应用时（停留） | 可以 |
| 回收页 / 画像页 | 可以 |

#### 约束二：不个性化——按时刻组织，不按用户状态

**曲库的组织维度只能是客观的：**

| 时刻 | 特点 |
|---|---|
| 清晨 | 轻、慢、不刺耳 |
| 午后 | 清醒、无歌词 |
| 深夜 | 低音、留白 |
| 雨天 | 环境音 |
| 通勤 | 短、有节奏、可中断 |
| 独处 | 安静 |

**绝不允许的维度：**

- ❌ 按用户当前情绪选曲
- ❌ 按用户历史偏好排序
- ❌ 「猜你喜欢」
- ❌ 「你最近压力大，听听这个」

**——后者不是关怀，是画像。**

#### 约束三：不宣称治疗——只说「咨询师选曲」，不说疗效

**「音乐治疗」是有资质要求的领域。**

**一旦文案出现「治疗」「疗愈」「改善焦虑」，就跨进了医疗行为。**

**允许的表述：**

```
✅ 「心理咨询师选的曲」
✅ 「适合已经累了一整天的人」
✅ 「和弦简单、没有突然的高音」
```

**禁止的表述：**

```
❌ 「治疗失眠」
❌ 「缓解焦虑的音乐」
❌ 「疗愈你的情绪」
❌ 「根据心理学的疗愈方案」
```

**选曲理由必须描述「音乐本身」，不能描述「你的病」。**

#### 约束四：默认关闭——用户主动打开，不能默认播放

**所有内容默认静音、默认不加载、默认不请求网络。**

**用户必须主动点开。**

**这一条防的是「陪伴型产品」的自动滑落——**

**一旦默认播放，绒球就从「工具」变成了「伴侣」，而伴侣型产品必须靠黏性生存。**

### 曲库规格

**每条曲目包含四个字段：**

```
曲名
时长
时刻标签（一个）
选曲理由（一句，不超过 30 字，只描述音乐）
```

**例：**

```
《夜曲》 · 深夜 · 4:12
「和弦简单，没有突然的高音，适合已经累了一整天的人。」
```

### 反馈规则

**用户反馈有两种，必须分开：**

| 反馈类型 | 能不能用 | 用在哪 |
|---|---|---|
| 「这首歌好不好」 | ✅ **可以用** | 优化曲库质量 |
| 「这个人需要什么音乐」 | ❌ **不能用** | 那是画像 |

**规则：**

> **反馈只作用于「曲子」，绝不作用于「人」。**
>
> **前者让人群变好，后者让人被定制。**

### 版权与成本

**不做重资产，不做独占曲库。**

| 项 | 做法 |
|---|---|
| 音乐来源 | 可商用授权（CC / Free Music Archive / 授权池） |
| 咨询师角色 | **策展，不是创作** |
| 核心能力 | 「怎么组合」「什么时刻放什么」 |
| 收费 | **不收费**（遵守日活层铁律一） |

**策展是你们的能力，创作不是。这个区分决定了成本结构。**

---

## 9.4 死亡风险：入口吃掉核心

**这不是合规风险，是产品史上最常见的死法。**

```
第 1 个月：  「加个声景，让入口有温度」          ✅
第 3 个月：  「用户 80% 时间在听音乐」           ⚠️
第 6 个月：  「要不做个歌单推荐？用户想要」       ❌
第 12 个月：  绒球变成了一个音乐 App，            💀
             判断功能在设置里
```

**原因很简单：**

> **日活层天生比核心层更有吸引力。**
> **而音乐，天生比做决定更有吸引力。**

**所以必须有一条硬规则，写进代码而不是文档：**

> **声景永远不能出现在「判断」这个 Tab 里。**
> **它只能是另一个 Tab，而且默认关闭。**

---

## 9.5 声景红线对照

| 红线 | 声景是否触碰 | 判定依据 |
|---|---|---|
| 一 · 不替用户做决定 | ✅ 不触碰 | 音乐不指向任何选择 |
| 二 · 他人观点零权重 | ✅ 无关 | 音乐不是事实 |
| 三 · 不卖注意力 | ✅ 不触碰 | 不收费、无广告；但**必须防「为听歌而停留」** |
| 四 · 内容不出设备 | ✅ 不触碰 | 只听歌，不上传任何偏好用于画像 |
| 五 · 不隐藏 | ✅ 不触碰 | 曲库公开、选曲理由公开、来源公开 |
| 安全例外 | ✅ 不冲突 | 危机界面不播放任何音乐 |

**最容易滑的是红线三：如果产品开始为「听歌时长」优化，就已经在卖注意力了。**

**所以声景的使用时长，不进任何考核指标。**

## M1 · 第三层完善（被问句库阻塞）

### 先纠正一个理解错误

**之前把半知理解成「系统替用户假设一个结论」——那是错的，把它降级成了猜测。**

**正确的定义：**

> **半知 = 系统已经找到、但用户还没确认的那一半第一接触面。**

```
N     事实面  =  信息在用户侧，已确认
1 半知        =  信息在系统侧，用户未确认
1 未知        =  信息不在任何一侧
```

**它不是猜测，是「已知但未确认」。**

### 三层完善

**用户得到一个决定的结构，要经过三次补全：**

| 层 | 补什么 | 谁提供 | 现状 |
|---|---|---|---|
| **第一层** | 用户说出的处境 | 用户自述 | ✅ |
| **第二层** | 全网同构场景 | 检索 + 用户确认 | ✅ |
| **第三层** | **原核另外的第一接触面** | **系统自主探测** | ⬜ **被阻塞** |

**前两层是被动的——用户不说，系统就没料。**
**第三层是主动的：系统拿着问句库，自己去把原核的面扫一遍。**

### 为什么现在必须让 11「死着」

**因为第三层的弹药是问句库。**

> **一句问句 = 一次探测 = 探测原核的一个潜在面。**

问句只有 2 句时，你只能探测 2 个面，**探出来的缺口不构成「另一半」**。

**问句库到 30–50 句、覆盖各类决定时，11 才有东西可算。**

**所以这不是没做完，是顺序问题：先有探测能力，再有半知。**

### 解锁条件

- [ ] 问句库扩展到 30–50 句（需要咨询团队供稿）
- [ ] 每个问句标注它探测的是哪一类面
- [ ] 系统能对同一个原核枚举出「还没被答到的面」

### 解锁后要做的事

1. **系统自主探测**：按原核类型，从问句库取出该问的面，扫一遍
2. **未确认的面进半知**：探到但用户没答的，进半知槽
3. **翻转阈值**：距离结论翻转还差几条事实
4. **还缺什么**：按类型列出常被忽略的面（清单，不是建议）

**关键：输出的是元信息，不是建议。**
> ❌「建议你去」 ✅「只差 1 条事实就会翻转」

# 十二、成功指标

## 12.1 绝不使用的指标

- ❌ 日活 / 时长 / 留存
- ❌ 广告收入
- ❌ 用户使用频次
- ❌ **声景的播放时长 / 播放次数**（一旦考核，产品就会为听歌优化——那就是在卖注意力）

**因为这些指标一旦成为目标，产品就会开始引导用户。**

### 特别说明：声景是唯一「看起来该有指标」的地方

**它天然会产生时长数据，而时长天然想被优化。**

**所以这里必须明说：**

> **声景不考核任何使用数据。**
> **曲库好不好，只看「用户说这首曲子对不对」，不看「听了多久」。**

## 12.2 唯一有效的指标

| 指标 | 定义 |
|---|---|
| **校准改善** | 用户的置信度与命中率之间差距是否收窄 |
| **判断回收率** | 归档的判断中，按期回来报告结果的比例 |
| **结构性使用** | 用户是否从「随便问问」转向「重要决定先过一遍」 |
| **依赖度下降** | 用户是否需要它越来越少（镜子的成功标准） |

# 十四、结论

**绒球要解决的不是「信息不够」，是「判断不清」。**

**它不生产答案，它生产清晰。**

**而第六章的六个潜藏能力说明了一件事：**

> **它真正的能力，不是「帮用户判断什么」。**
> **是「让判断本身变得可观察」。**

```
一次判断            →  答案
一百次判断          →  画像
一百次判断的结构     →  一个人的思维解剖图
```

**那才是它最后会长成的东西。**
