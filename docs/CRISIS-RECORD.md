# 危机本地记录（Crisis Record）

> 危机触发时，先把这一刻完整留在用户自己的设备上。
> 只写本机，不上传、不联网、不进入校准、不参与统计。

---

## 1. 它是什么

当输入命中轻生/自伤/绝望标签时，绒球立即停止判断，同时在本机写一份记录：

    data/crisis/<event_id>.json
    data/crisis/<event_id>.journal.jsonl   （当时的 journal 副本，如有）
    data/crisis/<event_id>.manifest.json   （SHA-256 清单）

记录内容包括：

- 当前请求的全部数据：问题、自述、勾选、回答、坐标等；
- 本地时间、UTC、时区、UTC 偏移；
- 当时的 journal 副本；
- 事件 ID、schema 版本、保存说明。

## 2. 它不是什么

- 不是云端备份；
- 不是警方接口；
- 不是家属自动通知；
- 不是产品分析数据；
- 不是用来训练模型的数据。

## 3. 完整性

每个事件有一份 SHA-256 清单：

- 记录 JSON 的哈希；
- journal 副本的哈希；
- 清单本身不含在哈希里，只描述被保存的文件。

校验命令（Windows）：

    certutil -hashfile <文件名> SHA256

哈希只能证明文件没有被改动，**不能证明内容真实，也不能证明作者身份**。

## 4. 本地导出

家属或警方在取得设备/合法授权后，可以主动导出：

    python scripts/export_crisis.py --list
    python scripts/export_crisis.py --event <event_id> --out exports/case1

导出目录包含：

- 原始事件 JSON；
- journal 副本；
- SHA-256 清单；
- README.txt（说明数据来源、时间、哈希校验方式）；
- SHA256SUMS。

导出工具只读本机 data/crisis/，只写用户指定目录，不联网、不上传。

## 5. 访问边界（重要）

**绒球不会自动把危机记录交给警方、家属或任何第三方。**

原因：

1. 如果用户知道「危机里说的话会自动交给别人」，最需要被接住的人会躲开；
2. 数据离开设备后可能被二次泄露、断章取义或用来指责当事人；
3. 产品无法判断谁有资格看、用户是否已经不在、家属是否善意；
4. 本地设备上的记录，警方依法调取设备即可；产品不建云端副本，反而少一条泄露路径。

因此：

- 默认只有设备持有者能打开；
- 导出必须由设备持有者主动执行；
- 未来如果做「紧急联系人 / 身后可见」，必须是用户生前明确设置、可撤回、走 B2 身份层，不默认开启；
- 不做隐藏后门，不做远程解锁，不做自动上报。

## 6. 删除

删除本地目录即可：

    data/crisis/

绒球不会在别处保留副本。加密要等 B1/B3 底座层，目前是本地明文文件，请自行保管设备。

## 7. 限制

- 只保存当前请求与 journal 副本，不保存设备级全盘数据；
- 无法验证记录是否由本人操作；
- 无法保证 journal 之前的数据完整（它只保存保存时刻的副本）；
- 不是司法鉴定报告，不能替代警方取证；
- 家属/警方使用时应遵守当地法律与最小必要原则。

## 8. 设计原则

- **接住人优先**：保存失败不能影响危机回应；
- **数据主权**：记录属于用户，不属于产品；
- **可核验**：哈希清单让「没有被改过」可以被检查；
- **不自动共享**：真相可以交给该交的人，但不由产品替用户决定；
- **不二次伤害**：导出说明里明确提醒，不要把它变成对当事人的指责材料。
