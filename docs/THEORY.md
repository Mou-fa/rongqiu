# 绒球 · 理论定稿（截至 2026-10-19）

这份文件记录经过反复纠正后定下来的原则。每一条都对应代码里的实现或明确的缺口。

## 0. 它是什么

**绒球是一个反聚合器。**

它不用别人的观点来判断，它帮用户用自己的独立思维看清自己的处境。
别人的看法不是外部力量，是回声；用回声校正主观判断只会更偏。

「借助外部力量修正主观判断」里的外部力量 = **客观事实**，不是他人看法。

## 1. 原核

用户问题的规范化三元组（代理·事件·资源），提取时剥掉时间、地点、修饰语。

用户往往会在一句话里说两件事：
- 他要判断的那件事 → **原核**
- 他顺带说出的处境 → **用户自述事实**

例：「今天身体不舒服，能不能去聚餐？」
→ 原核 我·参加·聚餐
→ 自述 我·身体不适·身体

## 2. 第一接触面的三个来源

| 来源 | 例子 | 权重 |
|---|---|---|
| **用户自述** | 「我今天身体不舒服」 | 最高（当事人本人） |
| **全网同主谓宾场景** | 「我参加聚会后经常觉得累」 | 事实候选 |
| **环境已知面** | 地区、天气、位置、时间 | 客观事实（未实现） |

## 3. 全网的文本就是数据库

不做「每个事物的第一接触面数据库」。靠组合词展开检索空间：

    聚餐 → 聚：聚会、聚拢 / 餐：餐厅、餐饮、餐食、餐盘、餐馆

这样整张网都成为候选库。**结构是普遍的，所以能全球化。**

## 4. 什么算事实

| 材料 | 算不算 |
|---|---|
| 真实发生的事件（谁和谁交换了什么） | 事实 |
| 用户自己的感受/模式 | 事实（使用者就是用户本人） |
| 他人的观点、评价 | 零权重 |
| 统计数据（80% 的人…） | 零权重，但可以弹出来当镜子 |

统计是**充分不必要条件**：刚好契合用户心理就帮他认领，不契合就跳过。

**REA 是交换事件模型，不是观点模型。**

## 5. N 是发现的，不是设定的

**N 是第一接触面的实际数量，由那个事物本身决定。**
复杂事物的接触面数量不固定，系统只能去发现，不能去设定。

**所以「把 N 做大」不是设计目标，是系统检索能力变强的自然结果。**

## 6. 811 算法

    可确定 = min(N/(N+2), 0.8) × 0.8^(链长-1)
    剩余 = 1 - 可确定，按 1:1 分给「假设」和「未知」

- N ≥ 8 时可确定封顶 80%，结构正好 8:1:1
- N < 8 时可确定更小，半知和未知对半分
- 三段相加永远严格等于 1

**「恒不变」的含义不是 N 固定是 8，而是那 20% 永远拿不到。**

### 半知到底是什么（2026-10-19 修正）

**之前理解错了：半知不是「系统替用户假设一个结论」。**

**正确的定义：**

> **半知 = 系统已经找到、但用户还没确认的那一半第一接触面。**

**这样 11 才真正对称：**

```
N     事实面  =  信息在用户侧，已确认
1 半知        =  信息在系统侧，用户未确认
1 未知        =  信息不在任何一侧
```

**它不是猜测，是「已知但未确认」。** 叫「假设」会把它降级成一个猜想，
叫「半知」才准确——**半只脚踩在已知里，因为系统确实找到了，只是你还没承认。**

### 所以 11 现在必须是「死的」

**在问句库建得差不多之前，半知槽填不出真东西。**

**原因：** 半知的内容来自「系统对原核另外那些第一接触面的探测结果」，
而探测靠的是问句库——**一句问句就是一次探测，探测原核的一个潜在面。**

问句只有 2 句时，你只能探测 2 个面，探出来的缺口不构成「另一半」。
**问句库到 30–50 句、覆盖各类决定时，11 才有东西可算。**

**所以这不是没做完，是顺序问题——先有探测能力，再有半知。**

## 6.5 三层完善（绒球的自主能力）

**用户得到一个决定的结构，要经过三次补全。前两次是用户给的，第三次是系统给的。**

| 层 | 补什么 | 谁提供 | 现状 |
|---|---|---|---|
| **第一层** | 用户说出的处境 | 用户自述 | ✅ 已实现 |
| **第二层** | 全网同构场景（用户可认领） | 检索 + 用户确认 | ✅ 已实现 |
| **第三层** | **原核另外的第一接触面** | **系统自主探测** | ⬜ 未实现 |

### 第三层是什么

**前两层都是「用户告诉系统的」。第三层是「系统主动去找用户还没说的」。**

具体做法：

1. 用问句库系统性地探测原核的接触面空间
2. 每个问句探一个潜在面
3. 用户答了的 → 进事实（N）
4. **用户没答的 → 进半知槽**
5. 谁都无法回答的 → 进未知槽

**所以第三层不是「多问两句」，是「系统自己知道该问哪些」。**

### 为什么这是「自主能力」

**因为前两层是被动的——用户不说，系统就没料。**

**第三层是主动的：系统拿着问句库，自己去把原核的面扫一遍。**

**它扫到的那些用户还没确认的，就是半知。**

**——这也是为什么 11 必须等问句库。第三层不是不会做，是弹药不够。**

## 7. 链长

每多一级推理，确定性乘以 0.8。0.8³ = 51%，0.8⁴ = 41%。
链长是**整条推理的属性**，不是单条证据的属性。
超过 3 级自动降到「暂定判定」。

## 8. 同源归并

三个朋友在同一个群说同一件事 → 一条证据。
十家媒体转载同一篇通稿 → 一条证据。
**标签不同不等于源头不同。**

但用户自述的每一条都是独立的处境，不因「都来自用户」而被归并。

## 9. 输出

**结构是主体，机器倾向只是小字。**

    原核
    用户自述的处境
    结构：第一接触面 N / 可确定 80% / 支持反对 a/b / 811 三分
    依据（全部公开，标注来源和方向）
    半知槽 · 未知槽
    系统参考倾向  ← 小字

## 10. 对错框架

用户提出问题，本身就说明他在犹豫。
系统不是告诉他答案，是把他心里模糊的结构摆清楚。

**假如系统判定不去，用户去了——都没错。选择权从来不在系统这里。**

## 11. 缺口

| # | 缺口 | 状态 |
|---|---|---|
| 1 | 环境已知面（地区/天气/位置/时间） | ✅ 已接入（只展示不计面） |
| 2 | 真实全网检索 | ✅ Tavily 已接 |
| 3 | 语音输入 | 只有 stub |
| 4 | 溯源回流仍是静态分级表，没有真正的逆向追踪 | 未做 |
| 5 | 主干/分支（自定义绒球）在代码里没有实体 | 未做 |
| 6 | 分形结构：接触点本身又是一个 N11 节点 | 未做 |
| 7 | 第三层完善：系统自主探测原核的另外第一接触面 | **被问句库阻塞** |
| 9 | 问句库覆盖度（当前 2 句，需要 30–50 句） | 需要咨询团队供稿 |
| 8 | 校准闭环跑真实数据 | 机器就绪，等数据 |
