## 为什么需要这份文件

**因为好产品不是被强敌杀死的，是被自己一步步「优化」掉的。**

历史规律：

```
今天加一个「推荐」
明天加一个「你可能需要」
后天加一个「为你优选」
最后：它变成了它反对的东西
```

**每一步都有理由，每一步都只走一小步，没有人是故意背叛的。**

**所以原则不能只写在文档里，必须写成可判定的条款。**

# 第一部分 · 五条红线

---

## 红线一：不替用户做决定

### 条款

**系统永远不输出「你应该做什么」。**
**系统只输出「你现在拿什么在做决定」。**

### 禁止清单

| ❌ 禁止 | 例子 |
|---|---|
| 给行动建议 | 「建议你去」「我推荐你参加」 |
| 推荐具体选项 | 「选 B 更好」 |
| 预测结果 | 「你去了会后悔」 |
| 个性化诱导 | 「大多数人像你这种情况都会去」 |
| 时间压力 | 「机会只剩 3 天」 |
| 情感操纵 | 「错过这次你会遗憾」 |

### 允许的表达

| ✅ 允许 | 例子 |
|---|---|
| 结构陈述 | 「3 个支持面，2 个反对面」 |
| 数值呈现 | 「更可能是：不会，置信 40%」 |
| 元信息 | 「距离翻转还差 1 条事实」 |
| 脆弱点提示 | 「这个判断建立在这条假设上」 |
| 缺口提示 | 「这类决定常被忽略的三项是……」 |

### 判定方法

**看输出里有没有「第二人称 + 祈使/建议」。**

```
❌ 你应该 / 你可以考虑 / 建议你 / 最好去 / 别去
✅ 你的结构是 / 置信度是 / 还差 N 条 / 依据是
```

**凡出现 ❌ 句式，一律视为违规。**

### 为什么

**因为一旦系统说了「去」，用户就不再是判断者，而是执行者。**
**那一瞬间，这个产品的全部意义消失。**

---

## 红线二：他人观点零权重

### 条款

**他人的看法、统计、专家意见，不得进入事实层。**

**唯一例外：真实发生的交换。**

### 事实层准入清单

| 可以进事实层 | 不可以进事实层 |
|---|---|
| 用户自己的陈述 | 网友评论 |
| 用户确认的场景 | 专家预测 |
| 成交价、成交量（真实交换） | 分析师目标价 |
| 官方发布的状态（天气、运行状态） | 媒体报道的观点 |
| 用户自己的历史行为 | 「大多数人说……」 |

### 禁止清单

| ❌ 禁止 |
|---|
| 按热度 / 点赞数给事实排序 |
| 把「很多人认为」作为论据 |
| 引用「行业共识」作为事实 |
| 用统计数字替代用户的具体情况 |

### 判定方法

**检查每个事实的来源字段（`source`）：**

```
用户自述     → 事实
用户确认场景 → 事实
真实交换价格 → 事实
官方状态     → 讯息（只展示，不计面）
他人观点     → 拒绝入层
```

### 为什么

**因为他人观点不是外部力量，是回声。**
**相关意见不携带新信息，聚合只会放大误差。**

---

## 红线三：不卖注意力，不卖数据

### 条款

**绒球的收入，不得来自用户的注意力或数据。**

### 禁止清单

| ❌ 禁止 |
|---|
| 广告（任何形式：横幅、信息流、原生） |
| 付费排名 / 推荐位 |
| 保险、贷款、理财、医美导流 |
| 出售、共享、交换用户数据 |
| 用「脱敏数据」变相交易 |
| 把用户决策记录用于广告定向 |

### 允许的收入

| ✅ 允许 |
|---|
| 企业版订阅（组织能力，非个人能力） |
| 机构授权（政府、智库、研究） |
| 部署与审计服务 |
| C 端订阅（仅「便利」功能，判断能力永远免费） |
| 公益基金 / 教育补贴 |

### 判定方法

**每年公开收入构成。**
**任何新收入来源，必须能回答：「这笔钱是否要求我们对用户施加影响？」**
**答「是」的，一律拒绝。**

### 为什么

**因为收入结构决定行为。**
**一旦广告成为收入，用户就不再是用户，是流量。**

---

## 红线四：不拿走用户能自己保管的东西

### 条款

**决策内容永不明文离开用户设备。**

### 数据分层（不可变）

```
设备端     ： 问题原文、处境、依据（明文，永不上传）
可选加密同步： 同上（端到端加密，密钥在用户手里，公司解不开）
云端       ： 是/否 + 置信度 + 结果 + 粗分类 + 模糊时间
公开层     ： 聚合统计（差分隐私）
```

### 禁止清单

| ❌ 禁止 |
|---|
| 明文上传判断内容 |
| 云端持有可解密密钥 |
| 服务端日志记录用户原文 |
| 第三方 SDK 采集行为数据 |
| 为「改进模型」而收集未脱敏数据 |

### 判定方法

**网络审计：抓一次完整使用流程的全部请求。**
**任何请求里出现用户输入的自然语言原文 → 违规。**

**代码审计：搜索所有对外发送数据的调用点。**

### 为什么

**因为「诚实的输入」是这个产品的全部原料。**
**而用户只有在确信没人在看时，才会诚实。**

---

## 红线五：不隐藏

### 条款

**任何结论，用户都必须能一路查到它的来源。**

### 必须公开的

| 项 | 要求 |
|---|---|
| 依据 | 每一条事实都能看到，可展开 |
| 置信度来源 | 说明这是启发式估算，不是测量 |
| 算法 | 811 计算方法公开 |
| 判断规则 | 什么算支持、什么算反对，公开 |
| 失败 | 判错过什么，公开 |
| 收入 | 年度公开收入构成 |

### 禁止清单

| ❌ 禁止 |
|---|
| 结论无法展开到依据 |
| 使用未公开的隐藏加权 |
| 隐瞒已知缺陷（如伪精确） |
| 把启发式包装成科学测量 |
| 删除对自己不利的数据 |

### 判定方法

**任意一条结论，点开后必须能看到：**
1. 全部事实面
2. 每一条的来源
3. 计数的过程

**任何一步缺失 → 违规。**

### 为什么

**因为不可验证的信任，不是信任，是赌。**

# 第二部分 · 三条算法不变量

**这几条不是产品层面的，是代码层面不可违反的。**

---

## 不变量一：可确定永远不超过 80%

```
可确定 = min(N / (N + 2), 0.8) × 0.8^(链长 - 1)
```

**无论 N 多大、链有多短，永不超过 0.8。**

**任何为了「让结论更确定」而调高上限的改动，一律拒绝。**

**理论依据：**
- 毛球定理：盲区是拓扑必然
- 必要多样性定律：世界无限，视野有限

---

## 不变量二：中性只存在于 11

```
事实层：support | oppose   （只有两种）
半知槽：1 条               （中性）
未知槽：1 条               （中性）
```

**任何给事实层加「中立」「不确定」「视情况而定」的改动，一律拒绝。**

**事实的判定必须给出方向。给不出方向的，就不是事实。**

---

## 不变量三：N 必须可追溯

**每一个事实面，必须能回答：**

> **这条事实是谁说的？**
> **它是用户自己确认的，还是系统找到的？**
> **用户点选了吗？**

**任何不可追溯的「事实」，一律不得进入计数。**

# 第三部分 · 灰区判定

**红线最难的不是遵守，是边界模糊时的判断。**

| 场景 | 判定 | 理由 |
|---|---|---|
| 「距离翻转还差 1 条」 | ✅ 元信息 | 陈述状态，不指向选择 |
| 「你可能忽略了家庭影响」 | ⚠️ 接近 | 「可能忽略」是提示；改成「这类决定常被忽略的三项是：家庭影响…」 |
| 「如果你把这条算进去，结论会变」 | ✅ 可接受 | 陈述机制，不是建议 |
| 「建议你先确认这条假设」 | ❌ 违规 | 祈使句 |
| 「大多数人遇到这种情况会去」 | ❌ 违规 | 他人观点 + 从众暗示 |
| 「天气：暴雨」 | ✅ 讯息 | 官方状态，不计面 |
| 「天气不好，别去了」 | ❌ 违规 | 建议 + 计面 |
| 「你的历史：类似决定你去过 3 次」 | ✅ 事实 | 用户自己的行为 |
| 「你以前都去了，这次也去吧」 | ❌ 违规 | 建议 |

**灰区判定原则：**

> **陈述「是什么」→ 安全**
> **暗示「该怎样」→ 违规**

**拿不准的时候，按「违规」处理。**

# 第四部分 · 执行机制

## 4.1 一票否决角色

**设一个「立场官」角色，具备以下权限：**

| 权限 | 说明 |
|---|---|
| 否决任何功能 | 不需要理由 |
| 否决任何合作 | 不需要理由 |
| 不向增长指标负责 | 考核口径是「红线零违规」 |
| 直接向创始人汇报 | 不经产品/商业线 |

**这个角色在任何规模下都必须存在。**

## 4.2 发布前检查清单

**每次发布，必须逐项确认：**

```
[ ] 新增输出里没有祈使句 / 建议句
[ ] 新增数据流里没有用户原文外发
[ ] 新增事实来源通过了准入清单
[ ] 80% 封顶未被修改
[ ] 事实层仍然只有二元
[ ] 每条结论仍可展开到依据
[ ] 新增收入来源通过了红线三判定
```

**任何一项未过，不得发布。**

## 4.3 违规的认定

**不区分「故意」和「不小心」。**

**只要能产生引导效果，就是违规。**

**「我们没那个意思」不是抗辩理由——用户的感受就是事实。**

# 第五部分 · 变更程序

**红线可以被修改，但程序必须极其昂贵。**

```
1. 提出：写明要改哪一条、为什么
2. 公开：在项目文档里公开这次变更
3. 冷静期：至少 30 天
4. 复核：立场官 + 至少一位外部审查者
5. 记录：永久记录变更历史，不得删除
```

**一条被轻易改掉的红线，等于不存在。**

# 结语

**一个产品的红线，不是在它成功的时候被检验的，**
**是在它有理由越过的时候被检验的。**

**那时候会有人说：**

> 「就这一次。」
> 「用户不会介意的。」
> 「这样能救活公司。」

**——这份文件存在的唯一目的，就是在那一天说「不行」。**
