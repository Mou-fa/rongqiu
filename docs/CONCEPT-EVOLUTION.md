# 概念演化记录 v0.1

日期：2026-10-22  
用途：以后判断「有没有偏离最初设想」时，先对**不变量**，不要对实现细节。

---

## 1. 三条不变量

1. **用户的问题就是原核。**  
   不是系统另造一个问题，也不是把用户的话改写成系统的问题。

2. **第一接触面的判断给出依据。**  
   判断不是凭「聪明的建议」，而是来自对用户自身处境的接触事实。

3. **输出是原核成立的可能性。**  
   不是「你应该做什么」，也不是对选项的排名。

除此之外，都是实现选择，可以变。

---

## 2. 旧处理为什么太固有化

之前把三件事当成了前置条件：

- 必须先抽出完整的 agent / event / resource，才能往下走；抽不出就不算入口；
- 第一接触面必须是一条事实，类别不算面，面只能是事实粒度；
- 结果必须一上来就是概率，结构分不算。

这三条把方法钉死了：用户的话稍微不规整，入口就卡住；面库难复用；概率变成假精确。

---

## 3. 当前扩展

### 3.1 原文先接触，原核后成形

- 现状：/api/ask 用原文做 surface 匹配和问句选择；原核解析并行进行——在线由 nucleus.parse 抽取，离线只得到 binary。
- 这不是绕过原核，而是允许「先接触，再让原核在接触中变清楚」。
- 待验证：问句是否因此更贴用户，而不是被一次错误的解析带偏。

### 3.2 面类别（surface）与第一接触面事实（contact fact）分离

- surface = 健康 / 时间 / 经济 / 风险……，是**面类别**；
- probe = 固定问句；
- 用户回答 = 一条 **contact fact**，方向由点击直接决定；
- 811 的 N = contact facts 数，不是 surface 类别数。

为什么扩展：类别让 probe 可复用、可按面校准；事实仍是判断单位。  
风险：表达不统一时，会把 13 个类别和 N 条事实混着叫「第一接触面」；文档和 UI 需要分开说。

### 3.3 结构置信度 → 校准后的可能性

- node.judge 先给结构分：confidence = min(det × (0.5 + |ratio − 0.5|), 0.8)；
- journal.p_yes 把它转成「原核为是」的概率目标；
- 在样本足够前，它是**结构置信度**，不是统计概率；
- 校准（Brier / skill / 按面）负责把它抬成概率。

## 5. 待验证假设（可证伪）

**H1：原文优先 + 类别选面，比「先完整解析原核再选面」更能覆盖真实问法。**  
判据：holdout 相关度、用户对问句的采纳率；不能靠文档自夸。

**H2：类别化 surface 能提高 probe 复用和按面校准，且不把 N 搞乱。**  
判据：13 类 vs 事实粒度的对比实验；N 仍然只数事实。

**H3：p_yes 会随样本增加收敛到真实发生率。**  
当前：16 条已回收，Brier 0.2557，skill −0.1901；样本不足，不能下结论。  
判据：Brier < baseline、skill > 0、可靠性曲线接近对角线。

**H4：在线 / 离线同问句策略不会导致判断分裂。**  
现状：211 个测试；在线/离线共用 surface 选择；打包版离线 smoke test 通过。

**H5：按面校准能解释「哪个面在骗人」。**  
当前观测：健康 20 facts / 35%，时间 19 / 52.6%，经济 17 / 70.6%，关系 13 / 84.6%，风险 13 / 76.9%。样本小，不作结论。

## 6. 评审清单（以后判断偏离）

- 用户的问题是否仍是原核？
- 判断是否仍来自第一接触面事实，而不是模型意见？
- 输出是否仍是可能性，而不是建议或排名？
- 是否把「实现选择」误当成了「不变量」？
- 是否为了覆盖率牺牲了不引导 / 可解释？
- 是否把 surface 类别和 contact fact 混为一谈？
- 概率有没有被校准，还是只是在叫概率？

---

## 7. 变更规则

- **改不变量**：必须写新版本，不能悄悄改。
- **改实现**：可以，但要在本页「当前扩展」记录原因和待验证假设。
- 每次重大版本更新本页，不删旧内容。
