## 4. 七条不可违反的原则

**这些是用户反复纠正后定下来的。改代码可以，改这七条要重新讨论。**

### ① 不给建议，只给结构

系统永远不输出「你应该做什么」。只输出「你现在拿什么在做决定」。

❌「建议你去」 ✅「只差 1 条事实就会翻转」

### ② 他人观点零权重

只有两种东西算事实：
- **用户自己的陈述**（最硬）
- **真实发生的交换**（成交价、可验证的事件）

网友评论、专家预测、统计数字、媒体报道 —— **全部零权重**。
全网红文本只作为「镜子」给用户看，**用户认领了才算事实**。

### ③ 事实二元，中性只存在于 11

事实层只有「支持 / 反对」，**没有中间地带**。
中性只存在于半知槽和未知槽。

不作弃权 —— 不决定本身就是一种决定。

### ④ 80% 是封顶，不是目标

```
可确定 = min(N / (N + 2), 0.8) × 0.8^(链长 - 1)
```

**N 再多也超不过 80%。那 20% 永远拿不到。**

### ⑤ N 是发现的，不是设定的

一个问题有几个第一接触面，由那个事物本身决定。
**「把 N 做大」不是设计目标**，是检索能力变强的自然结果。

### ⑥ 环境讯息不计面

时间、地点、天气 **只展示，不进任何一格**。

> 环境是场，不是面。它影响判断，但它不属于「你这个人身上的东西」。

### ⑦ 判向看「会不会做」，不看「想不想做」

「我最近很累」对「去聚餐」是**反对**——不是因为不想，是因为去不了。

**反复想 = 在乎 = 想去**（这类信号判支持）。

## 5. 半知和未知的准确定义

**这一条曾经理解错过，写清楚：**

```
N     事实面  =  信息在用户侧，已确认
1 半知        =  信息在系统侧，用户未确认
1 未知        =  信息不在任何一侧
```

**半知不是「系统替用户假设一个结论」**，是「系统已经找到、但用户还没确认的那一半第一接触面」。

**推论（2026-10-20 已更新）：11 从「必须是死的」变成「第一版活了」。**

因为半知要靠「系统拿问句库去探测原核的另外接触面」才能填，
而问句库只有 2 条时，探出来的缺口不构成「另一半」。

**填一个假半知，比空着更糟。**

**现在的做法：** 系统按原核挑 8–12 条（`questions.select`）；用户没答的面 → 半知槽。
规则没变：半知永远不进 N、不改变方向。

## 7. 已知技术陷阱

### ① JS 的 TDZ（踩过两次）

`let` / `const` 声明在函数调用之后 → ReferenceError，页面卡在「加载中」。

**已经踩过**：`show()` 漏掉危机面板、`SS_LOADED` 声明在 `switchTab` 后面。

**规则**：页面初始化时会用到的变量，全部声明在文件顶部。

### ② PowerShell 写文件会带 BOM

`Set-Content -Encoding utf8` 在 PS 5.1 下加 BOM，Python 读出来开头是 `\ufeff`。
**读的时候用 `encoding="utf-8-sig"`。**

### ③ 中文脚本必须 UTF-8 BOM 或纯 Python

PowerShell 执行含中文的 `.ps1` 需要 UTF-8 BOM。**优先用 Python 处理中文。**

### ④ API key 已在 git 历史里

Tavily 旧 key 在 4 个提交里（已作废，新 key 只在本地 `configs/search.yaml`）。
**推公开仓库前记得这件事。**

### ⑤ 用 `hash()` 做持久化缓存 key（2026-10-20 已修）

Python 的 str `hash()` **每个进程随机化**，拿它做文件名 = 换个进程就永远命中不了缓存。
`search.py` 的搜索缓存原来就是这么写的，攒了几百个永远用不上的文件。
**规则：持久化 key 一律用 `hashlib.sha1` / `md5`，不用内置 `hash()`。**
